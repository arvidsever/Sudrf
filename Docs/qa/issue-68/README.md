1. Чистая классификация TLS/certificate, DNS, timeout, connection/offline,

2. Ограниченный локальный индекс метаданных, отдельно от базы дел. Успех
   фиксируется после пригодного разбора существующей операции источника;
   распознанная пустая выдача допустима. HTTP 200 или распознавание CAPTCHA

3. Подключение исходов существующих search/card операций четырёх клиентов,
   ошибок отдельных судов до объединения движения, auto/manual/fallback

## Retention host в индексе

При чтении и записи индекса сохраняются все host из явно переданного набора
`trackedHosts`, независимо от возраста наблюдения, и не более 50 остальных
host с наиболее поздним `lastObserved`. Если даты совпадают, первыми остаются
лексикографически меньшие имена host. Набор применяется заново при каждом
вызове: если caller перестал считать host отслеживаемым, тот конкурирует за
место в пределах 50 по времени наблюдения.

`load(trackedHosts:)` применяет правило и к ранее созданному индексу без
лимита; `save(_:trackedHosts:)` атомарно записывает уже ограниченное состояние.
Аргумент обязателен, без значения по умолчанию. Код runtime-операций пока не
подключён; будущий caller должен передавать текущие host дела из собственного
источника tracked-case identity, не из отображаемого имени.

## Безопасный индекс

`SourceHealthIndex` сохраняет только проверенные `SourceHealthState.Fact` в
`Application Support/Sudrf/diagnostics/source-health-index.json` атомарной
JSON-записью. При чтении host, family и каждое значение проверяются повторно;
ошибка декодирования или записи возвращается вызывающему коду, файл при этом
не переписывается. Индекс пока не подключён к сетевым операциям. Retention
ограничивает только число неотслеживаемых host; отслеживаемые записи никогда
не вытесняются этим правилом.

Изолированный профиль `SourceHealthIndexTests`, `SourceHealthStateTests` и
`CaptchaSolverLogTests`: **21 XCTest, 0 failures, 0 skips**. Помимо проверки
записи/повторного чтения, независимых фактов host, игнорирования небезопасной
строки из файла, отвергания подложных HTTP-200 успеха и отмены при чтении,
ошибки чтения и ошибки записи без изменения соседнего файла, retention
проверен на старом индексе с 55 отслеживаемыми и 54 прочими host. Сохраняются
все отслеживаемые и 50 самых новых прочих; равные даты разрешаются по имени.
Отдельно проверены сырые ключи файла сразу после сохранения исходного
переполненного состояния, повторное чтение и снятие host с tracked-набора.
Для candidate retention добавлены 51 старый файл в temp-dir и проверено, что
после записи остаются 50 самых новых; посторонний `.txt` сохраняется.
Для PNG-предела отдельно проверен старый файл с расширением `.PNG`.

## Чистое состояние каждого host
