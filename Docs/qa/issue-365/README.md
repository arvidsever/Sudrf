# #365 — понятные названия судов в списке дел

Проверка исправления ведётся на изолированной копии хранилища. Рабочая база,
её sidecar-файлы, TestFlight и графический интерфейс не используются. В снимке
не публикуются номера дел, стороны и другие персональные сведения.

## Причина

При сборке движения `Movement.shortCourtName(forDomain:)` сохраняет в
`CaseInstance.court` первый сегмент хоста, если суд не найден в справочнике.
Кэшированные домены вида `OBLSUD--MO.SUDRF.RU` не совпадали с точечным,
строчным доменом Московского областного суда: `CourtDirectory.court(forDomain:)`
сравнивал строки без нормализации. Поэтому технический label попадал и в
`StoredSession.court`. В `AppRouter.makeTrackedCase` подпись ближайшего заседания
инстанции пересмотра имеет приоритет над названием корневой записи, и эта
подпись видна в «Моих делах».

В исходной изолированной копии было 469 отслеживаемых записей; аудит родителя
обнаружил 41 техническое название суда в кэшированных инстанциях, при этом
названия корневых записей не содержали технических значений. В частности,
домен `OBLSUD--MO.SUDRF.RU` подтверждён в кэше апелляционной инстанции.

## Исправление и границы

- `CourtDirectory.court(forDomain:)` приводит домен к регистронезависимой
  канонической форме СудРФ, одинаковой для точечного и двойного тире.
- Для будущего заседания инстанции пересмотра название берётся из справочника
  по домену той же исходной карточки. Связь определяется сохранённым
  `sourceCardID`; для старых снимков используется только уникальное совпадение
  номера и инстанции вместе с названием суда. Неоднозначное событие не получает
  название корневого суда.
- Для старых/неполных данных общий resolver выбирает название справочника,
  затем читаемое название исходной карточки события только при совпадении
  канонического домена, уровня и номера. В строке корневой записи используется
  её сохранённое название, затем название суда из её же контекста. Технический
  ASCII-код, хост, URL и пустой placeholder не отображаются.
- Не меняются схема и wire-протокол; исходные данные и кэш при открытии не
  переписываются. Календарь, лента и другие поверхности не расширялись.

## Автоматические проверки

`CourtDirectoryTests.testCourtForDomainResolvesCaseAndDashAliases` проверяет
верхний/нижний регистр, оба варианта хоста и полный URL с путём.
`CourtNamePresentationTests.testReadableCourtNamePrefersDirectoryAndHidesTechnicalFallback`
проверяет приоритет справочника, безопасный fallback, placeholder и читаемые
кириллические сокращения. Тесты `MovementDerivationTests` проверяют разрешение
домена именно связанной карточки и запрет заимствовать название корневого суда
при неоднозначном событии. Тест `MyCasesModelTests` проходит полный путь
проекции карточки и проверяет номер апелляции, дату заседания, название суда
события и отдельное название суда корневой записи.

Опциональный headless-аудит запускается на копии изолированного снимка:

```sh
SUDRF_COURT365_AUDIT_STORE=/path/to/isolated/audit.store \
  swift test --filter MyCasesModelTests.testIssue365AllIsolatedTrackedCaseCourtProjectionsAreReadable
```

Тест копирует входной файл во временную директорию, загружает его через
`AppRouter`, сравнивает количество сохранённых и спроецированных записей,
повторно строит проекцию после `reload()` и считает технические значения сразу
в `court` и `recordCourt`. В вывод пишется только агрегат.

## Доказательства изолированного аудита

- Вход: `/private/tmp/sudrf365-store-audit/audit.store`, 469 записей.
- SHA-256 входного файла до аудита:
  `f49423453a6bdf3263b519d7f0535cac2cb747aafd3bc6255516805863410598`.
- Исходная база и её sidecar-файлы не открывались и не изменялись; проверка
  integrity и исходных хешей выполнена до запуска теста.
- Повторный аудит полного снимка: `ISSUE365_AUDIT records=469 projected=469 technical=0 genericFallbacks=0`.
  Технические значения не появились ни в `court`, ни в `recordCourt`; ни одной
  общей подстановки «Суд» вместо известного названия нет. Повторное построение
  проекции после `reload()` совпало с первым; хеш входа после теста неизменен.
- Профильные наборы справочника и представления: 72 теста. Регрессии проверяют
  две карточки на общем московском портале: корневая карточка не получает
  название соседнего вышестоящего суда.
- Полный набор `swift test` прошёл: 702 SudrfKit, 1067 SudrfApp,
  10 FSSPCaptchaLab и 75 CaptchaSolver tests; 11 ожидаемых пропусков
  опциональных live/visual тестов, ошибок нет. Шесть прежних ожиданий полного
  названия 3 КСОЮ заменены именем того же суда из справочника; проверки стадии,
  номера производства, даты заседания, обновления и повторного открытия сохранены.
- Пересоздан Xcode-проект; `xcodebuild` Debug собственной сборки 0.61.5 (231)
  завершён успешно. Проверка registry подтвердила актуальность генерации.

Визуальная приёмка не выполнялась и для этой проверки не заявляется.

## Доводка после живой проверки — 4 октября 2026 года

Пользовательский экран подтвердил правильное название в строке списка и два
сырых `OBLSUD--MO` в заголовках открытого движения. Предыдущий аудит проверял
`TrackedCase.court` и `recordCourt`, поэтому не обнаружил другой путь вывода.

`InstanceBlock` используется общей карточкой движения в «Поиске» и «Моих
делах», включая материалы. Его заголовок и сообщение о временной недоступности
напрямую показывали `instance.court`. Подключён существующий
`CourtNamePresentation.readableCourtName` по домену и собственному сохранённому
названию инстанции. Исправление применяется сразу к старому кэшу; запрос к суду
не нужен. Исходная модель, её ID, ссылки, события и сырые названия не меняются.

Проверка выполнена на синтетическом JSON-кэше и собственном представлении
`InstanceBlock`; рабочая база и TestFlight не использовались. Выпуск доводки:
**0.61.7 (233)**, PR [#401](https://github.com/arvidsever/Sudrf/pull/401).

Регрессия `CaseMovementViewTests.testCachedAppealBlocksDisplayDirectoryCourtAfterJSONRoundTrip`
создаёт общие блоки для `33-9548/2026` и `33-42895/2026` после загрузки старого
JSON. Оба показывают «Московский областной суд» при raw `OBLSUD--MO` и dot/dash,
mixed-case доменах. Исходные `court`, `domain`, ID, ссылки и события сохранены.
Профильный набор: 7 тестов; окончательная регрессия после уточнения фикстуры
проверена отдельно. Независимый review производственного diff пройден.

[Собственное проверочное представление](movement-court-names.png) получено
через `ImageRenderer` того же `InstanceBlock`, на синтетических данных, без
запуска приложения. Оно не является снимком рабочей базы пользователя.
