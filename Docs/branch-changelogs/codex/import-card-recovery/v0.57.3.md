# v0.57.3 — восстановление ссылок импортированных дел

Черновик ветки `codex/import-card-recovery`; номер версии уточняется перед merge.

- Неработающие ссылки федеральных судов SUDRF восстанавливаются в два шага:
  проверка подходящих параметров картотеки с прежними идентификаторами,
  затем поиск по УИД или точному номеру в том же суде. Новая ссылка принимается
  только после загрузки и проверки самой карточки.
- Работающие исторические ссылки сохраняются. Временная недоступность суда,
  CAPTCHA и сетевые ошибки не являются основанием для замены адреса.
- Исправление адреса сохраняет досье, подборки и последний успешный кэш;
  повторный импорт старой ссылки не должен отменять восстановление.
- Для незагруженных дел показывается результат последней попытки, а отчёт
  импорта различает восстановление адреса, неоднозначность и отказ источника.

## Подтверждённый исходный дефект

7 сентября 2026 года в запущенном Sudrf 0.57.2 (163) через Xcode beta
проверены 33а-852/2022 (ВС Республики Коми) и 66а-4311/2020 (Первый АСОЮ).
Ссылки `delo_id=5&new=5` возвращали HTTP 200 с оболочкой сайта без карточки;
`delo_id=42&new=0` с теми же `case_id`, `case_uid` и `srv_num` возвращали
ожидаемую карточку и движение. Обезличенные excerpts и SHA-256 captures:
`Tests/SudrfAppTests/Fixtures/card-recovery/`.

Для 9а-118/2022 зафиксирован временный отказ источника; исправление адреса
не доказано. `MDB_MAP_FULL` не включён в исправление: связь с этими отказами
не установлена.

## Проверка

- Xcode beta / Swift 6.4: полный `swift test` — 1164 теста, 5 штатно
  пропущены, ошибок нет. После прогона дополнительно проверены 13 тестов
  `CaseCardRecoveryTests` (включая три новых проверки УИД/пустоты) и новый
  транспортный тест `SudrfClientCompleteSearchTests` — без ошибок.
- Подписанная Debug-сборка `xcodebuild` и штатная универсальная упаковка
  `Scripts/make-app.sh --ci` (arm64 + x86_64) прошли. Номера release-версии и
  билда не менялись; архив является проверкой ветки, а не новым выпуском.
- Проверены rollback сохранения, удаление во время запроса, повторный импорт
  старого URL после временного отказа, восстановленная апелляция при сохранении
  якоря первой инстанции и история восстановленного неякорного участника
  группового импорта. Проверены raw query Windows-1251 через настоящий транспорт,
  `srv_num`, перенаправление на чужую карточку и неполная поисковая выдача.
- Пользовательские изменения `Localizable.xcstrings` сохранены без изменения
  (SHA-256 `99692375b8a06e888453c7d1a1bcab21014031c0de12237c8b2db1ba882b02e2`).
- Живая приёмка: новая подписанная сборка открыла 545 дел, включая 539 дел
  последнего импорта. Штатное обновление выполняется; окончательный подсчёт
  адресов и отказов будет внесён после его завершения.
  Обычным открытием подтверждены сохранение адреса и загрузка движения:
  33а-852/2022 и 66а-4311/2020 — `5/5` → `42/0`;
  9а-118/2022 — `1540005` → `41/0` после восстановления доступности источника.
  Во всех трёх случаях сохранены исходные `case_id`, `case_uid` и `srv_num`.
  Статус движения частичный из-за остальных звеньев цепочки; он не означает
  повторного отказа исходной карточки.
