## Минимальный полный объём после согласования

1. Чистая классификация TLS/certificate, DNS, timeout, connection/offline,
   HTTP, parser/unknown page и CAPTCHA с безопасным коротким описанием.
2. Ограниченный локальный индекс метаданных, отдельно от базы дел. Успех
   фиксируется после пригодного разбора существующей операции источника;
   распознанная пустая выдача допустима. HTTP 200 или распознавание CAPTCHA
   сами по себе не подтверждают успех.
3. Подключение исходов существующих search/card операций четырёх клиентов,
   ошибок отдельных судов до объединения движения, auto/manual/fallback
   CAPTCHA и факта создания диагностических файлов. Один общий refresh
   всей цепочки не доказывает исход каждого сайта.
4. Согласованный экран с открытием и очисткой только собственных диагностических
   артефактов. Дела, акты, corpus и рабочий search-variant cache не очищаются.
5. Проверки классификатора, индекса, отсутствия секретов, ограничений хранения,
   сбоя записи и независимости обычной работы от наличия диагностики.
   Проверки используют временные каталоги и подменённые ответы.

Новые сетевые проверки, telemetry, изменение SwiftData schema и TLS policy
для этого объёма не требуются. Макет предшествует реализации интерфейса;
визуальная приёмка обязательна до слияния. Финальная версия назначается
после полной реализации и приёмки; текущая подготовка не является выпуском #68.

## Подготовленная независимая часть

Общая чистая `SourceTransportFailureCategory` в `SourceOutcome.swift` используется
прежней TLS-проверкой `SudrfClient` и отчётом `PortalCanary`. Все семь TLS-кодов
прежнего клиента сохранены. Единственное изменение результата CLI — ошибки
клиентского сертификата также относятся к `tls`, вместо общей `network`.

Вычисляемая `SourceAttempt.transportFailureCategory` использует только уже
сохранённый числовой код транспортной ошибки. HTTP, другие исходы и
отсутствующий/нечисловой код не получают сетевую категорию. Отмена имеет
отдельную категорию; это не новое правило записи отмены в историю здоровья.
Новых Codable-полей нет. Краткие сообщения, индекс, UI и retention ещё
не реализованы; три открытых решения не обходятся этой подготовкой.

Независимый review исходников и тестов: блокирующих замечаний нет. Матрица
проверяет TLS, DNS, timeout, connection/offline, отмену и неизвестный код;
отдельно проверяются NSError с кодом −1200, transient wrapper, сохранённый
JSON без новых полей и CLI с подменённым сетевым отказом.

## Чистое состояние каждого host

10 октября 2026 года добавлена внутренняя App-модель `SourceHealthState`.
Она хранит независимо последнюю попытку, последний подтверждённый успех и
последнюю ошибку каждого host. Успех требует явного подтверждения собственной
операции этого host; агрегированный результат цепочки и HTTP 200 недостаточны.
CAPTCHA и partial не становятся успехом. Отмена обновляет только наблюдение.
Запоздалые ответы не вытесняют более свежие факты; при равном времени сохраняется
первый факт.

Mutable/decoded provenance повторно проверяется на входе: только DNS host
подходящего семейства, конечная дата, допустимый HTTP status, числовой код
ошибки и положительное число попыток. Произвольные сообщения, URL query и
`affectedSources` в модель не копируются. Модель находится в App, без нового
публичного API SudrfKit, runtime-подключения, сохранения на диск или UI.

Профиль `SudrfAppTests.SourceHealthStateTests`: **5 XCTest, 0 failures,
0 skips**. Проверены независимая хронология и соседний host, собственное
подтверждение, отмена, повреждённые/приватные строки после декодирования,
соответствие семейства домену и равные даты. Общие настройки, системные
сервисы и пользовательские данные не инициализируются.
