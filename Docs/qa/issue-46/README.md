## Установлено по текущему коду

- `RootView.swift:142`: подготовка начинается в `.task` оконной сцены.
- `RootView.swift:105–109`: подготовленный контейнер передаётся `AppRouter`,
  запускается фон, затем публикуется `.ready`.
- `AppModel.swift:508`: router устанавливается в `SudrfIntentRuntime` синхронно.
- `AppModel.swift:517–520`: каталог устанавливается позднее, в отдельном `Task`,
  после запуска `refreshCenter`. `.ready` не является барьером его установки.
- `SpotlightIntegration.swift:175–194`: без установленного каталога registry
  возвращает пустые массивы. `AppIntentsIntegration.swift:20–24` без router
  выдаёт `applicationUnavailable`.
- `SudrfApp.swift:19–26`: delegate не устанавливает каталог или router.

Это обновляет устаревшие ссылки на строки и место установки каталога в issue,
но не устанавливает, поднимает ли macOS оконную сцену до разрешения параметров
и выполнения фоновой команды.

[Документация Apple о runtime](https://developer.apple.com/documentation/appintents/configuring-the-runtime-behavior-of-your-app-intents)
описывает `supportedModes` как предпочтение, на которое также влияют место
исполнения и условия системы. Она не подтверждает порядок нашего bootstrap.
Изменять режимы или добавлять второй контейнер на основании одной гипотезы нельзя.
