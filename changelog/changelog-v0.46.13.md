# v0.46.13 — надёжное продолжение поиска после ручной CAPTCHA

## Исправлено

- Ошибка навигации после ручной отправки CAPTCHA теперь сразу возвращает форму
  в состояние повторной попытки, а не оставляет её ждать 60-секундный watchdog.
- Навигации связываются с конкретной попыткой: отменённые, чужие и запоздавшие
  callbacks предыдущей отправки не могут завершить новый retry.
- После принятого кода токен сохраняется для канонического хоста, CAPTCHA-лист
  закрывается и исходный поиск продолжается с прежними судом, картотекой и запросом.
- Локальная диагностика `CaptchaAssist` фиксирует только attempt, HTTP status,
  host, path и классификацию результата — без кода, captchaid, cookies, HTML,
  поискового запроса, query string и fragment.

## Установлено расследованием

- Исторические deadlock-защиты существовали до пользовательского репорта о
  версии 0.40, поэтому точная причина того инцидента не доказана.
- Подтверждён текущий самостоятельный дефект: JS-submit без прежнего navigation
  marker мог получить реальную ошибку навигации, которую интерфейс игнорировал
  до watchdog.
- 30 августа 2026 года ручной flow проверен на актуальных формах Ленинского
  районного суда г. Оренбурга и Санкт-Петербургского городского суда: неверный
  код дал новую форму, а правильный закрыл лист и продолжил исходный поиск.

## Совместимость

- Публичные API, SwiftData V6, migration plan, рабочий UI и форматы хранения не
  изменились. Автоматический session-unlock мировых судей остаётся в #164, а
  продолжение проверки КСОЮ — в #88.
