# #359 — границы слов в заголовках актов

Проверочное приложение использует настоящие `CourtActContent` и `ActWindowView`
на синтетической санитизированной карточке № 2-7212/2025. Оно не запускает
`SudrfApp`, не открывает рабочую базу и не пишет в системный Spotlight.

## Воспроизведение

```sh
bash Docs/qa/issue-359/run.sh
SUDRF_HEADING359_QA_OUTPUT="$PWD/Docs/qa/issue-359" \
    /private/tmp/SudrfHeading359.app/Contents/MacOS/Heading359
```

В проверочном приложении нажать Command-R. Проверка сохраняет `panel.png`,
`window.png`, `heading.pdf` и извлечённый `heading-extracted.txt`.
Результат — `/private/tmp/sudrf-359-gui-result.txt`.

## Контракт

- В панели, отдельном окне и текстовом PDF виден заголовок «ЗАОЧНОЕ РЕШЕНИЕ».
  Межбуквенная разрядка является оформлением шрифта; межсловный пробел остаётся
  частью текста. В опубликованные исходные PDF это оформление не вносится.
- HTML-парсер и paragraphizer по-прежнему могут схлопывать расстояние между
  словами. Нормализация представления восстанавливает только известные заголовки,
  в том числе для старых сохранённых абзацев; обычную прозу не исправляет.
- Spotlight получает тот же канонический текст и переиндексирует старые записи
  по изменённому fingerprint. Проверка использует изолированный manifest и
  записывающий тестовый адаптер, а не системный индекс.
- Исходный текст, hash, версия paragraphizer, границы и ID абзацев сохраняются.
  Несколько визуальных блоков одного сохранённого абзаца имеют общий paragraphID.
