# #360 — предыдущие номера без повтора заголовка

Проверка 3 октября 2026 года на синтетической истории номеров. Рабочая база,
TestFlight и графический интерфейс не запускались. Пользователь указал выполнить
исправление без визуальной приёмки; снимки не требуются и не заявляются полученными.

## Автоматическая приёмка

Проекция `AppRouter.caseNumberAliases` удаляет из `previous` все номера, уже
отображённые в полном составном заголовке, включая `~`, `∼`, скобки, знак `№` и
различия регистра. Алиасы `searchable` не фильтруются этим правилом, записи истории
и привязка к конкретной исходной карточке сохраняются. Существующий заголовок
`CaseMovementView` выводит строку только при непустом массиве `previousCaseNumbers`.

## Что проверить позднее

«Мои дела» → дело `2-7212/2025 ~ М-5922/2025` → движение: строка
«Предыдущие номера» не должна повторять эти два номера. При наличии другого
прежнего номера, которого нет в заголовке, он остаётся в строке. Поиск/фильтр
по прежнему номеру должен по-прежнему находить дело.
