# v0.58.30 — Диагностика фонового обхода

Первый этап #68 добавляет локальный обезличенный отчёт штатного фонового
обновления, необходимый для gate #180 перед разработкой нового scheduler.

- Каждый завершённый или отменённый обход сохраняет отдельный атомарный JSON в
  `Application Support/Sudrf/diagnostics` с ограничением в 20 отчётов.
- Отчёт содержит длительность обхода, число eligible и завершённых записей,
  задержку в очереди и после наступления eligibility, возраст последней попытки
  и полного успеха, typed source outcomes и transport retry count.
- CAPTCHA, partial, maintenance, transport и parser failures агрегируются по
  каноническим host; отдельно фиксируется продолжение работы на другом host
  после отказа источника.
- Судебные обновления отделены от enforcement-only проверок. Номера дел,
  стороны, внутренние ключи, URL, cookies, токены и CAPTCHA-коды в отчёт не
  попадают.
- Отменённые поколения обхода не смешиваются с новым запуском; существующий
  порядок очереди, TTL, retry и пользовательские проекции не изменены.

Публичные API, SwiftData-схема, semantic derivation version и интерфейс не
изменены. Реальный baseline на 200+ eligible-делах снимается отдельно штатным
non-force запуском; #68 и #180 остаются открытыми.
