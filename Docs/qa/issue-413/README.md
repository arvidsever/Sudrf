## Воспроизведённая причина

Оба исходных ответа разобраны неизменённым `MosGorSudCardParser` в отдельном
пакете, содержащем только SudrfKit и диагностические тесты.
SHA-256 файла парсера:
`327d837bfc46f2b455e26dedb72207973a9302d4c8d602a5f7501ca72f74983d`.

В обоих ответах собственный номер опубликован в паре `div.left` / `div.right`
с меткой «Номер жалобы ~ дела». Текущий поиск поля пропускает эту метку
и выбирает «Номер дела в суде нижестоящей инстанции».
Поле «Суд первой инстанции, судья» одновременно выбирается для собственных
`court` и `judge`. Совпадение с УИД примера сохраняется и не предотвращает
подмену реквизитов.

При построении найденной верхней инстанции номер строки выдачи сохраняется,
но суд из подробной карточки получает приоритет. Штатный парсер выдачи
не заполняет собственное поле суда. Поэтому правильный номер апелляции
сочетается с реквизитами нижестоящего суда. Прямое открытие и проверка
происхождения дополнительно могут отклонить карточку из-за неверного номера.

Диагностические проверки завершились без ошибок: отдельно одна карточка,
затем обе карточки. Они фиксируют фактически неправильный результат,
а не подтверждают правильное поведение приложения. Историческая причина
конкретной пользовательской записи без чтения этой записи не устанавливалась.

## Контрольная точка исправления

В отдельной ветке исправлены собственные поля номера, суда и судьи.
Клиент передаёт опубликованный URL для проверки собственного судебного
контекста; найденная апелляция проверяется по собственному номеру и имеющимся
УИД до подтверждения загрузки источника.

Изолированный пакет только SudrfKit прошёл класс `MosGorSudTests`:
После устранения замечаний scope и сопоставления районного названия:
38 тестов, 0 ошибок, включая восемь регрессий #413. Копии изменённых
исходников, теста и двух фикстур побайтово совпадают с веткой.
SHA-256 локального журнала проверки:
`f7dbbb2d7de747f227ec087bfbcc821416a2d7e9730be78d6bcef875a91fb386`.
Обычные targets приложения в этом пакете отсутствуют.

Предшествующий RED-прогон по ошибке использовал общий пакет репозитория:
он скомпилировал targets приложения, хотя выбраны были только профильные
тесты. Это не изолированный Kit-only прогон; запуск приложения и тестов
других targets не выполнялся. Последующая проверка выше использовала
отдельный ограниченный пакет. Полной проверкой приложения она не является.

Первый независимый статический review принял свежий источник; замечание о
разных временах получения двух карточек исправлено в provenance. Изменения
выбора результата, даты вступления в силу и вышестоящего номера восстановлены
до прежнего поведения. Дополнительные тесты проверяют эти поля, короткое и
полное московское название районного суда и отклонение чужого суда/города.
Финальный diff после этих изменений ещё требует независимого review.
