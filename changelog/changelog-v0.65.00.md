# v0.65.0

Подключён первый этап мировых судей Москвы — дела по КоАП.
Каждый действующий участок показывается отдельно в существующем выборе суда;
его название и код берутся из опубликованного справочника. Участки сортируются
по опубликованному номеру участка (8, 9, 10, 48, 89, 90),
а опубликованный URL участка остаётся отдельным идентификатором. Поиск по номеру,
УИД или участнику ограничивает выдачу выбранным участком. Ведущие нули в
номере не мешают совпадению, номер участка и год остаются частью проверки.

Найденная карточка открывается по точной ссылке выдачи. Кэш движения
повторно используется только для той же native-карточки; номер участка и
номер дела без совпадающего UUID источника не подтверждают совпадение. Сохранённый поисковый
контекст используется при фоновом обновлении. Подключён маршрут участка,
районного суда и пересмотра в Мосгорсуде, затем существующие федеральные этапы.
Связь с районной жалобой проверяется по согласованной совокупности признаков
для единственного кандидата; общий УИД сам по себе не доказывает связь.

Транспорт использует HTTPS с обычной проверкой сертификата; чужие redirect и
смена native ID карточки отклоняются. Полнота поиска, пагинация и пустая выдача
пока не подтверждены: полезные данные сохраняются как частичный результат,
не продлевая достоверность всей цепочки. Первый этап с этим ограничением
уведомлений согласован: изменения участка не подтверждаются для журнала,
пока полнота источника не доказана. Вложения актов самого участка этим
этапом не подключены. Импорт московских мировых через CSV и прямую ссылку
остаётся незавершённой частью #248; ГПК и КАС — частью открытой #106.

Контракт сверялся с разрешённым reference `aptumyc/sudtudtestbot` на commit
`0ec0cc73bc0b23324a514f8298d858bc62fabb1c`. HTML выдачи и движения в регрессиях
синтетический. Сокращённая фикстура справочника получена с официального сайта;
476 опубликованных записей включают 471 действующий участок и 5 отменённых.
Alias, код, ID записи, групповой ID и URL сохраняются раздельно. ID участка
читается из опубликованного URL, не выводится из номера строки или названия.

Один живой путь поиска и найденной карточки прошёл проверку 9 октября 2026 года;
это не подтверждает полноту выдачи. Проверка собственного УИД карточки
использует запрос, сохранённый вместе с выдачей; до проверки контекст добавления
недоступен. Автор принял нативный офлайн-порядок участков и выбор
10 октября 2026 года. На интегрированном commit исполнены обе дисковые регрессии,
проверки точной карточки и identity без УИД; release commit проверяется
собственным CI перед merge.
Этот первый этап не завершает и не закрывает #106.

Первое сохранение и полное обновление используют один точный идентификатор
карточки участка, независимо от наличия судебного УИД. Регрессия проверяет
отсутствие второго дела и сохранение журнала после повторного открытия базы.
