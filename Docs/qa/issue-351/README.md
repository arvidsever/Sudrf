# Приёмка #351: дни соседних месяцев

Проверено 30 сентября 2026 года на macOS 27.2, Xcode 27.0.
Все события вымышлены, `ModelContainer` находится в памяти. Рабочая база и
TestFlight не открываются; `RootView` и фоновый bootstrap приложения не запускаются.

## Результат

- Общая неделя 28 сентября — 4 октября 2026 года показывает одинаковые записи в
  сентябре и октябре. 28 сентября: 10:00, 10:30, 12:05, 14:00; 1 октября: 11:15;
  4 октября: 09:00. Основное дело, апелляция и материал представлены отдельно.
- Ячейка показывает действующий срок, историю, накладку и честное «ещё 3».
  В октябре соседняя накладка видна, но месячный счётчик равен нулю.
- AX-тесты нажимают соседние даты и проверяют сохранение месяца, обновление
  событий, Месяц/Неделя, «Эта неделя» и открытие кэшированного дела без refresh.
  Результат GUI-прогона: **3 теста, 0 ошибок, 0 пропусков**.
- Отдельные чистые тесты проверяют 4/5/6 недель, декабрь–январь, високосный февраль,
  исключающие границы диапазона, сохранение ID, подписей судов, накладок и серий
  «N из M» для полного календарного месяца события.
- Снимки: сентябрь и октябрь при 1280 × 760 pt в обеих темах; стресс-сетка при
  760 × 660 pt; панель дня при минимальном размере основного окна 1180 × 720 pt.
  На узком воскресенье дата, история и накладка сохраняются.

## Повторение

```sh
swift test --filter CalendarMonth
bash Docs/qa/issue-351/run.sh
```

В собственном окне «Sudrf — календарь #351, синтетические данные» прочитать
дерево доступности через Accessibility Inspector или UI automation, затем
нажать **Command-R**. Это включает AX в SwiftUI и запускает ту же тестовую
классификацию `CalendarMonthViewTests`, которую использует `swift test`.
В CLI два AX-теста честно пропускаются, когда `NSHostingView` не предоставляет
дерево; проверка снимков и чистая модель выполняются всегда.

Хост собирается из тестового класса и `GUIHost.swift`, используя testable-объект
приложения; его entry point заменён тестовым, собственный bundle ID —
`ru.sudrf.qa.calendar351`. Снимки появляются в `/private/tmp/sudrf-351-hosted/`,
результат — в `/private/tmp/sudrf-351-gui-result.txt`. Ненулевые ошибки или пропуски
GUI-тестов дают ненулевой код завершения. Самостоятельный хост завершается после
проверки. Статический ImageRenderer-снимок можно сохранить также через переменную
`SUDRF_CALENDAR_VISUAL_OUTPUT` при обычном запуске тестов.

В этом каталоге сохранены снимки настоящего `NSHostingView`, включая системные
кнопки. `gui-result.txt` относится к приложенному синтетическому примеру.
