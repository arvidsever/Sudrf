# #156: межрегиональный поиск регистрации по УИД

Проверка от 9 октября 2026 года. Ветка перебазирована на main
`aaa1bce3c4ed86d16a4a659fa082c056c0b72049` (после PR #425, версия 0.62.11).
Интерфейс и схема хранения не менялись.

## Причина

Суд из `r_juid` сопоставлялся со справочником, выбранным по префиксу УИД.
При межрегиональном переходе URL карточки мог указывать на другой регион,
а поиск справочника отклонял правильный районный суд. Дополнительно выдача
по парным картотекам отбрасывала новые нативные карточки, если их номер дела
совпадал с уже найденным.

Проверка суда теперь выбирает официальный список по региону опубликованного
URL, сверяет домен и название и оставляет допуск только для районного суда.
Загрузка продолжается по точной опубликованной ссылке; ответ проверяется на
совпадение судебного УИД и номера, а перенаправление — на целевой домен.
Дедупликация регистраций использует точные непустые `caseID` + `caseUID` на
каноническом домене. Точный прежний номер с другим native ID сохраняется.
Подавляется только строка предварительного материала, классифицированная как
потенциальная основная карточка того же суда, если уже загруженная совпадающая
составная карточка также относится к этому каноническому суду.

## Автоматическая проверка

Команда профильного набора:

```sh
swift test --scratch-path /private/tmp/sudrf156-kit-diagnosis \
  -Xswiftc -strict-concurrency=complete \
  --filter 'Issue321|Issue94RegistrationHistoryTests|Issue288RegistrationDiscoveryTests|MovementCachePolicyTests|MovementServiceTests|MovementDedupTests'
```

Результат: 87 тестов `SudrfKit` и 9 тестов `SudrfAppTests`, ошибок нет. В том
числе проверены:

- выбор региона назначения по URL карточки и проверка районного суда;
- отдельная выдача двух native ID с одним номером;
- сохранение cross-court карточки с тем же составным номером и same-court
  основной карточки, если fetched-карточка содержит предварительный alias;
- подавление предварительного alias только при совпадении канонического суда
  загруженной карточки; B→A порядок не скрывает отдельную регистрацию A;
- дедупликация точного известного зеркала и одинаковой пары native ID/GUID;
- сохранение регистрации после частичного, честно пустого и ошибочного
  обновления, закрытие и повторное открытие временного дискового контейнера;
- существующая регрессия, запрещающая повторное добавление основного дела
  через предварительный номер-псевдоним.

Межрегиональный тест — синтетическая мутация санитизированной фикстуры
#321 в памяти. Он не является захватом такого перехода и не подтверждает
текущую доступность судов. Достаточное основание остаётся прежним: строка
`r_juid`, совпавшие судебный УИД и номер карточки, официальный список и
название районного суда. Дополнительная проверка исхода передачи не добавлялась.
Подробный provenance фикстур находится в
`Tests/SudrfKitTests/Fixtures/issue321_fixture_provenance.md`.
