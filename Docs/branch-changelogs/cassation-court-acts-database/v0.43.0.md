# v0.43.0 (черновик ветки `claude/cassation-court-acts-database-xwrhwx`)

Подготовка к сбору правовой базы судебных актов кассационных судов ОСЮ. В этой ветке —
только то, что относится к `SudrfKit`: сам харвестер, база и поиск живут отдельным
серверным проектом.

## Добавлено

- **`SudrfURLBuilder.srvNum`** — номер экземпляра базы суда. У крупных судов их несколько
  (наблюдались 1…3), и дела распределены между ними: запрос только к первому возвращает
  неполную выдачу, причём молча — суд отвечает валидной страницей без недостающих строк.
  Параметр применяется единообразно к форме, выдаче и карточке (дело, найденное на втором
  экземпляре, и карточку отдаёт со второго). По умолчанию `1` — прежнее поведение
  сохранено побайтово.
- **Ключи вариантов поиска различают экземпляр базы** (`primary:srv2`, `vnkod:…:srv2`):
  `WorkingVariantStore` кэширует рабочий вариант по id, и вариант, сработавший на одном
  экземпляре, не должен подставляться вместо другого.
- **`Docs/architecture/ksoyu-listing-grammar.md`** — грамматика перечня дел КСОЮ
  (`name_op=r` без поискового запроса): параметры картотек, диапазоны дат поступления,
  рассмотрения и публикации акта, пагинация `&page=N`, ротация `srv_num`, структура строки
  выдачи со ссылкой на текст акта, поведение капчи. У каждой строки указан провенанс
  и статус проверки, потому что источники разной свежести.

## Заметки

- В документе зафиксировано расхождение по `delo_id` кассационных картотек: три внешних
  источника требуют для выдачи нормализованные значения (`2800001` / `2450001`), а
  `CartotekaRegistry.cassationSOYu` хранит короткие (`5` / `4`). Правка отложена до живой
  проверки — для карточки и поиска по номеру текущие значения работают.
- Клиентская ротация `srv_num` в `SudrfClient` не включена: это изменение поведения
  приложения, его нельзя вносить без прогона на живых судах.

## Тесты

- `URLBuilderTests`: значение по умолчанию не меняет URL и не задваивает параметр;
  `srv_num` доезжает до формы, выдачи и карточки; кассационная выдача КСОЮ несёт
  и `srv_num`, и `delo_table`; ключи вариантов при разных экземплярах не пересекаются;
  значение меньше единицы поджимается к первому экземпляру.
