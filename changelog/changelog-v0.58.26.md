# v0.58.26 — Независимое обновление вышестоящих инстанций

Исправление #237. Временная недоступность базовой карточки больше не блокирует опрос вышестоящих судов по ранее подтверждённому судебному УИД.

- Сохранённые higher-court targets продолжают обновляться при CAPTCHA, технических работах, сетевых/HTTP-ошибках и ошибках разбора базового источника; отсутствие locator базовой карточки также не мешает обходу.
- Fallback разрешён только для полного валидного судебного УИД. Технический GUID, неполный или отсутствующий УИД не запускают поиск по эвристике.
- HTTP 404/410 сохраняют существующий путь восстановления адреса карточки; отмена операции и локальные ошибки контекста не превращаются в частичный успех.
- Успешные ответы заменяют только собственную часть движения, а данные недоступных host восстанавливаются из последнего успешного кэша. Частичное обновление не продлевает TTL полного успеха и не создаёт событий журнала.
- CAPTCHA базового суда получает одну штатную попытку автосолва. При неуспехе свежие данные вышестоящих судов сохраняются, а точная форма базового host остаётся в существующей очереди ручного ввода; последующий полный refresh очищает очередь.
- Повторный partial refresh и перезапуск изолированной дисковой базы сохраняют одну запись, акты, историю, подборки и подтверждённые данные без дублей.

Публичные API, SwiftData-схема, scheduler, UI и механизм прямой загрузки сохранённых `sourceURL` не изменены; последний остаётся задачей #238.
